# Wilson Survival Agent 阶段报告（供 Astral 评审）

日期：2026-09-25
环境：macOS／Steam《饥荒联机版》，单人私有测试世界，Wilson
当前游戏 Mod：`wilson_p0_probe` 0.7.0；本机 Python 桥接：`probe/bridge.py`

## 1. 项目目标与当前判断

最终目标是让 Wilson 在 DST 中自主完成观察、探索、采集、补给、制作、避险和发展，逐步达到地表为主的 70 天生存。沿用原移交文档的三层设计：Lua／Python 处理感知、执行和即时安全；Jev 从代码提供的可执行候选中做战术取舍；高层 LLM 调整中长期目标。

**当前已证明 Wilson 能在一个局部资源场景中，无需人逐条下命令，连续选择并完成三次采集。尚无证据表明它能独立探索、度过昼夜或持续生存。** 现阶段实际运行的是确定性规则选择器，尚未在本项目运行 Jev 或战略 LLM，也没有产生模型调用费用。

## 2. 已落地的工程链路

```text
DST 服务端 Mod 读取 Wilson 状态和附近实体
    → 每 1 游戏秒向本机 127.0.0.1:8765 发送短 HTTP 请求
    → Python 返回当前命令或空命令
    → Mod 校验玩家 GUID、请求序号、bridge epoch、命令 ID 和有效期
    → 执行动作，回传状态、位移或背包物品增量
    → Python 根据回传结果决定下一步
```

- 感知范围：Wilson 的生命、饥饿、理智、昼夜阶段、位置，以及 8 游戏单位内最多 12 个指定实体；目前识别草、小树苗、浆果丛、部分掉落物和青蛙。资源状态取自 `pickable:CanBePicked()`，可见性经游戏脚本筛选。这个局部筛选尚未证明与玩家屏幕视野完全等价。
- 动作能力：一次短距离移动、一次较长的向东移动、对指定草／小树苗／浆果丛的 `ACTIONS.PICK`。采集完成要求目标变为不可采，并且主背包中对应物品数量增加。Mod 会对目标、距离、背包容量和附近可见青蛙再次检查。
- 自主采集：本机显式启动后，白昼且生命、饥饿均不少于 75 时，从观察到的资源中选最近可采目标；等上一动作确认完成，再选下一目标。单次测试最多确认五次采集；资源采空、条件不满足或失败时会结束或停止下发。当前不会自动进食、制作光源或跨区域寻找资源。
- 运行和排查：Mod 已安装到 Steam 游戏目录，与项目源文件逐字比对一致。桥接日志写入 `/private/tmp/wilson_bridge.log`，可用 `tail -f /private/tmp/wilson_bridge.log` 在 Terminal 查看动作与结果。

## 3. 验证记录与证据级别

| 项目 | 实际结果 | 证据级别 |
| --- | --- | --- |
| Mod 与双向 HTTP | 私有世界中主服务器加载 Mod；Wilson 状态连续发送，收到匹配序号的 HTTP 200 回执。桥接服务暂时断开时游戏继续运行，恢复后继续交换。 | 真实游戏 |
| 状态观察 | 读到生命、饥饿、理智、昼夜阶段；用户走近资源后，实际返回浆果丛和小树苗相对位置。 | 真实游戏 |
| 单次移动 | 短移动在游戏里多次产生约 1.5 单位位移，用户目视确认。 | 真实游戏 |
| 单次采集 | 对指定草执行采集，日志显示 `started → completed`；目标从 `ready=true` 变为 `false`，背包增量为 1。 | 真实游戏 |
| 连续自主采集 | 0.7.0 自动依次采两株草（GUID 109283、109285）和一株小树苗（GUID 104382）；三个命令均报告 `started → completed`，每次完成后才选下一目标，累计 3 次、失败 0 次。 | 真实游戏 |
| 固定方向移动尝试 | 资源采空后曾自动向东移动约 7.99 单位；该动作没有目标或地图依据。收到用户反馈后，已从自主模式移除。 | 真实游戏；已撤销该策略 |
| 五次采集上限 | 模拟五个目标的桥接消息，确认逐次完成和达到上限后关闭。 | 本机模拟，尚未在游戏中凑满五次 |
| 显式停止命令 | 代码与本机模拟已完成；真实游戏尚未测试。人工接管测试在 0.5.0 做过一次，当前按用户优先级暂缓继续投入。 | 停止命令未实测 |

第一版 Mod 曾因 Lua Mod 环境中直接调用 `pcall` 导致主服务器报错和断线；改为 `GLOBAL.pcall` 后重新进游戏，通信与动作测试均正常。这是已经修复并经实际加载复测的问题。

## 4. 对原设计阶段的核对

| 阶段 | 当前状态 |
| --- | --- |
| P0：本机环境、双向接口、最小动作 | 主要通路与真实动作已验证。玩家退出后重新进入、旧命令和迟到回执的完整会话测试尚未完成。 |
| P1：行为生命周期、进度、失败与本地危险处理 | 已有单次采集状态和有限连续采集；目标外的移动规划、受阻恢复、危险抢占及夜间生存尚未形成闭环。 |
| P2：Jev 战术选择 | 尚未开始本项目的真实调用。现有规则选择器可作为后续对照基线。 |
| P3 以后：战略 LLM、早期生活、70 天 | 尚未开始。 |

用户已明确调整优先级：接下来以“Wilson 能否独立玩”为主线，人工接管的细节暂缓。即时安全、动作结果判断和过期命令隔离仍是自主运行的必要底层能力。

## 5. 当前最大缺口与拟议下一步

当前循环只会采集 8 单位内已看见的资源；采空便结束。固定向东走一步的试验说明，仅有位移不能算探索。接下来拟先做**有观察依据的目的地选择**：记录已观察区域和可见资源，选择具体目标或待观察的邻近区域，执行一段受限移动，依据新观察和实际位移判断进展或受阻。之后补齐最初几天必需的进食、光源、工具／制作和危险处理，再在少量经过真实游戏验证的候选行为之间接入 Jev。

这一路线仍需逐项实测。尤其不能把“局部采集三次成功”外推为安全无人值守、游戏知识可靠、Jev 优于规则或 70 天生存可行。
